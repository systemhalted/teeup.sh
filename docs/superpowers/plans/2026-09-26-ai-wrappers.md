# Per-command AI wrappers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the first call of one AI command install only that command's capability, skip already-complete requirements, show immediate mise progress, recover after an interrupted download, record lazy work once in `$TEEUP_STATE_DIR/logs/lazy.log`, and preserve `teeup install ai` as the explicit five-tool bundle.

**Architecture:** Replace the single five-command provider with five `tier=lazy` leaf capabilities: `ai-claude`, `ai-codex`, `ai-gemini`, `ai-copilot`, and `ai-opencode`. Each leaf owns one `provides=` token and one mise wrapper; the existing `ai` capability becomes an aggregate whose `requires=` lists the leaves. `cmd_install` skips a requirement whose `cap-<name>` done marker exists but always runs the requested target, so repair semantics stay intact. `cmd_lazy_run` assigns a lazy log only after consent, generated wrappers append their download transcript to the same file, and `run_logged` carries a capture-depth environment marker so nested runners do not append the same line twice.

**Tech Stack:** bash 3.2 (macOS stock), BSD `sed`/`awk`/`grep`/`find`, mise, file-existence state under `$TEEUP_STATE_DIR`, the mock-binary harness in `tests/helper.sh`, and timestamped shell migrations.

**Spec:** `docs/superpowers/specs/2026-09-11-omarchy-inspired-redesign-design.md`, section 6 and its amendment dated 2026-09-26.

**Runs:** after the current `b1ef603` checkout. The migration stamp `1790392758` is the live checkout's last commit epoch and is greater than the two shipped migration names, `1790302919.sh` and `1790311423.sh`.

## Global Constraints

Every task's requirements implicitly include this section.

- **bash 3.2 compatible.** Do not use associative arrays, `mapfile`, `readarray`, `${var,,}`, `readlink -f`, `wait -n`, `&>>`, or `**`. Keep indexed-array expansions guarded when an array can be empty. Avoid a quoted slash pattern inside `${var//pattern/replacement}`; bash 3.2 mis-parses that form.
- **BSD tools only.** Do not add GNU-only flags, `grep -P`, or GNU `sed` syntax. `date '+%Y-%m-%d %H:%M:%S'`, `mktemp -d`, `mkfifo`, `tee`, `sed -n`, and `grep -qxF` used below are available on macOS.
- **State means completed capability work.** A done marker may skip a capability only when it is a requirement of the requested target. The requested target always runs install and configure so `teeup install <cap>` remains the repair path and `lazy-run` can restore a command removed by hand.
- **One command means one leaf.** `claude` routes to `ai-claude`, `codex` to `ai-codex`, `gemini` to `ai-gemini`, `copilot` to `ai-copilot`, and `opencode` to `ai-opencode`. Only the explicit `teeup install ai` bundle visits all five leaves.
- **The stable wrapper marker stays byte-for-byte unchanged:** `# teeup mise wrapper; regenerated by: teeup configure ai`. Existing wrappers must remain teeup-owned after the split. User-facing repair text names the leaf owner passed to `mise_wrapper_write`; the marker is compatibility data, not current help text.
- **An interrupted install is retryable.** `mise use -g --quiet <tool>` may write the global request before its download is interrupted. The next call must detect `requested` and run `mise -C / install <tool>`, preserving a pinned version and reaching `mise x` only after success.
- **Progress is immediate and on stderr.** Before the first missing runtime or CLI is installed, print exactly `Installing <display name> through mise (first run, can take a minute)...`. Keep `--quiet` on `mise use`; the explicit line supplies the missing feedback while mise errors and any emitted progress still reach the terminal.
- **Lazy logs.** A consented `lazy-run` defaults `TEEUP_LOG_FILE` to `$TEEUP_STATE_DIR/logs/lazy.log`; a direct wrapper call derives the same default. The file records capability brackets, the progress line, mise output, completion, and failure. A declined prompt, an already-present real command, and every `DRY_RUN=true` path create no lazy log.
- **Nested logging appends once.** The outermost non-interactive `run_logged` owns the two tees. Nested runners print into those inherited streams and do not append or tee independently. Stream separation, exit-status preservation, interactive behavior, and the explicit wait for both outer tees remain unchanged.
- **Dry run mutates and claims nothing.** It may print `[DRY-RUN] Would ...`; it must not create logs, wrappers, shims, done markers, mise requests, or installed-tool records. An already-installed wrapper command may still execute because there is no pending mutation.
- **Ownership and honesty.** A foreign file or symlink in `~/.local/bin` is preserved. Configure names a wrapper only when `MISE_WRAPPER_WRITTEN=true`; removal claims a wrapper only after checking it is gone. A failure leaves the relevant done marker in place for a retry.
- **Tests stay in temporary roots.** `TEEUP_MACHINES_DIR` defaults to the checkout, so any test that can load a machine file exports `TEEUP_MACHINES_DIR="$TEST_HOME/machines"`. Tests may read shipped migrations and capabilities but write only under `$TEST_HOME` or another `mktemp -d`; `tests/run.sh`'s checkout snapshot must stay unchanged.
- **Prompt tests disable gum.** Every test that can reach `ui_confirm`, `ui_input`, or `ui_choose` exports `TEEUP_NO_GUM=1`. Use `TEEUP_TEST_TTY=yes|no` for the lazy terminal branch.
- **Printed fixes work.** A test must run or directly exercise each changed repair instruction, including `teeup install <leaf>`, `teeup configure <leaf>`, and the interrupted-install retry.
- **Suite counts are discovered, not pasted.** `tests/run.sh` ends with `All N suites passed.` Do not hard-code `N`; compare the suite count before and after a task when a suite file is created or removed. This plan creates no test suite file, so the suite count stays constant.
- **Plain prose.** Comments, messages, docs, and commit bodies follow the repository's direct style and the root `AGENTS.md` restrictions on rhetorical clichés.
- **Every task ends with** `./tests/run.sh` green, `./bin/teeup commands --check` silent with exit 0, `./bin/teeup dev check` green, CI's full shellcheck command from `.github/workflows/ci.yml` silent, `git diff --check` clean, and **one** commit with a plain imperative subject and no trailer of any kind. Do not add `Co-Authored-By`, `Claude-Session`, or generated-by attribution.

## Contracts this plan publishes

1. **Leaf capability names and providers.** `ai-claude:claude`, `ai-codex:codex`, `ai-gemini:gemini`, `ai-copilot:copilot`, `ai-opencode:opencode`. Every leaf is `group=ai`, `tier=lazy`, `requires="mise"`, and has exactly one `provides=` token.
2. **`ai` compatibility aggregate.** It remains a real lazy capability and menu target. Its `requires=` is the five leaf names and its `provides=` is empty. `teeup install ai` installs missing leaves and skips leaf requirements already done. `teeup remove ai` removes teeup-owned wrappers for all five leaves and clears their leaf state; a failed leaf removal leaves `cap-ai` marked for retry.
3. **`cmd_install <target>`.** Resolve the full `cap_order`. For each `c != target`, skip install/configure when `state_done check "cap-$c"` succeeds and log `Already installed: <c> (required by <target>)`. A missing requirement and the target itself still run through `cap_install_verbs`.
4. **`TEEUP_RUN_LOG_CAPTURED=true`.** Set only in the environment of the command owned by the outermost non-interactive `run_logged`. While present, `_teeup_log_line` prints without direct append and nested `run_logged` executes without starting another tee pair.
5. **`mise_wrapper_write <owner> <display-name> <command> <tool> [runtime...]`.** `owner`, `command`, `tool`, and runtimes are plain tokens; `display-name` is trusted shipped copy and may contain spaces. It keeps the stable marker, sets `MISE_WRAPPER_WRITTEN`, names `teeup configure <owner>` in repair text, prints one progress line per wrapper invocation with missing tools, logs the install transcript, and ends with `exec mise x ...` only after every tool exists.
6. **`mise_wrapper_remove <owner> <command>`.** Preserve absent and foreign paths, delete only a stable-marker wrapper through `run_cmd`, check the result on a real run, and return non-zero if an owned wrapper remains. Its fix is `teeup remove <owner>`.
7. **Lazy log location.** The default is `$TEEUP_STATE_DIR/logs/lazy.log`. An explicit non-empty `TEEUP_LOG_FILE` remains authoritative, which lets callers redirect a diagnostic run. Wrapper code derives `TEEUP_STATE_DIR` from `XDG_STATE_HOME`/`HOME` when teeup was not its caller.
8. **Legacy migration.** `migrations/1790392758.sh` runs once. If `cap-ai` is done, each existing `~/.local/bin/<command>`—regular file, working symlink, or dangling symlink—maps to the matching leaf marker. Any absent path leaves that leaf unmarked and clears `cap-ai` so `teeup install ai` can repair the incomplete bundle. Foreign paths are inspected only for existence. The migration refreshes `teeup-runtime` when that capability exists and is done, replacing old `lazy-run ai <command>` shims with leaf routes.

## Decisions made here

1. **Use `ai-<tool>` leaf names.** The prefix keeps five related entries together in `teeup list`, avoids making the command name silently mean both a binary and a bundle, and leaves `ai` available as the established all-tools command.
2. **Keep `ai` as an aggregate capability.** Removing it would turn a documented command and menu action into an error. An alias in `bin/teeup` would hide the dependency graph from `cap_order`, `teeup commands --check`, removal checks, and status.
3. **Skip only done requirements.** Skipping the target would break repair after a hand-deleted binary or wrapper. Re-running every requirement caused the 35-second first call and the unwanted `brew update`; the state marker is the project's explicit record that the requirement completed.
4. **Keep mise's `--quiet`.** A single teeup progress line fixes the apparent hang without replacing mise's stable quiet behavior with backend-dependent download chatter. Any output mise does emit is still shown and logged.
5. **Use one append-only lazy log.** Capability install/configure and wrapper download are one user action. Sharing `TEEUP_LOG_FILE` gives a chronological transcript without a second log-discovery rule.
6. **Migrate state from paths, not mise downloads.** A leaf capability installs a wrapper lazily; its done marker says setup completed, not that mise has downloaded the CLI. Existing command paths are therefore the correct legacy evidence. The migration never runs a CLI, queries the network, or deletes a file.

```bash
#!/usr/bin/env bash
# Split the old five-command ai capability into one lazy capability per command.
# A fresh bootstrap has current metadata and marks this migration applied. On an
# existing machine, cap-ai says the old configure completed; each command path
# says which leaf setup still exists. The contents and symlink targets are not
# teeup's to inspect or change here.

if cap_exists ai-claude; then
  if state_done check cap-ai; then
    ai_split_complete=true
    for ai_split_pair in \
      ai-claude:claude \
      ai-codex:codex \
      ai-gemini:gemini \
      ai-copilot:copilot \
      ai-opencode:opencode
    do
      ai_split_leaf="${ai_split_pair%%:*}"
      ai_split_command="${ai_split_pair#*:}"
      ai_split_path="$HOME/.local/bin/$ai_split_command"
      if [[ -e "$ai_split_path" || -L "$ai_split_path" ]]; then
        state_done mark "cap-$ai_split_leaf"
      else
        ai_split_complete=false
        warn "The legacy ai setup has no $ai_split_path, so $ai_split_leaf was left unmarked."
      fi
    done
    if [[ "$ai_split_complete" != "true" ]]; then
      state_done clear cap-ai
      warn "The legacy ai setup is incomplete. Its working commands were kept; repair the bundle with: teeup install ai"
    fi

fi

# current configure regenerates managed shims from the five leaf provides= rows
# and leaves foreign files alone. Fixture trees used by CLI tests may omit it.

fi
```
